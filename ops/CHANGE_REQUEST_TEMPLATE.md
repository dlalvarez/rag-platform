# Solicitud de cambio de arquitectura / ADR

**ID / Autor / Fecha / Estado:**

1. Problema concreto y evidencia.
2. Principios/contratos afectados (Pxx, ADR, Fxx).
3. Propuesta y alternativas reales, incluida no hacer nada.
4. Impacto en bases de tenants, `rag_control`, datos, secretos, vectores, objetos, migraciones, API, costos y operación.
5. Amenazas nuevas y mitigaciones.
6. Compatibilidad y plan de migración (sin asumir facilidad), rollback y pruebas.
7. Riesgos residuales y documentación que se actualizaría.
8. **Decisión humana:** Aprobado / Rechazado / Pospuesto, fecha y responsable.

Codex puede recomendar el cambio, pero **no aprobarlo ni implementarlo unilateralmente**.
